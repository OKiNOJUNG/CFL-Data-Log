# ADR-0002: หน่วยของ "งาน" และความเป็นเจ้าของข้อมูล

- **สถานะ:** ยอมรับแล้ว
- **วันที่:** 2026-10-06

## บริบท
นักวิจัยทุกคนดูข้อมูลของกันและกันได้ แต่คนที่ เพิ่ม/แก้ไข/ลบ ได้ต้องเป็นเจ้าของงานเท่านั้น
จึงต้องกำหนดให้ชัดว่า "งาน 1 ชิ้น" คืออะไร

## การตัดสินใจ
- **โปรเจกต์ (Project)** = งาน 1 ชิ้นของนักวิจัย สร้างจาก **ข้อมูลตั้งต้นตามไฟล์แนบที่ 4**
  (Batch Medium no., Experiment no., Condition, Feed culture, Date, Seed, Seed preparation)
- ใน 1 โปรเจกต์มี **Batch ได้หลายรอบ (ทำซ้ำ)** และ 1 Batch = ไล่จากถังแรกจนถึงถังสุดท้าย **ครบ 8 ถัง**
  (PF → F2 → F3 → F4 → F5 → F6 → F7 → D3)
- ค่าตั้งต้นของโปรเจกต์ (สภาวะ/การเจือจาง) **ถูกล็อกไว้ทั้งโปรเจกต์** ทุก Batch ใช้ชุดเดียวกัน
  ถ้าเปลี่ยนสภาวะ ต้อง **สร้างโปรเจกต์ใหม่**
- **เจ้าของโปรเจกต์** = ผู้สร้าง มีสิทธิ์ เพิ่ม/แก้ไข/ลบ ทุกอย่างภายในโปรเจกต์ ผู้ใช้อื่นอ่านได้อย่างเดียว

## โครงสร้าง
```
Project (header ไฟล์แนบ 4, owner)
 └── Batch #1..n (ทำซ้ำ)
      └── Tank × 8 (PF..D3)
           └── Sample @ time point (h)
                ├── Brix
                ├── Cell count (Total/Budding/Dead × 5 ช่อง)
                └── HPLC (Sucrose, Glucose, Fructose, Ethanol, Glycerol)
```

## ผลที่ตามมา
- เทียบ Batch ซ้ำภายในโปรเจกต์ได้ (ค่าเฉลี่ย ± SD) และเทียบข้ามโปรเจกต์ได้ (หา Condition ที่ดีที่สุด)
- ใน Firestore Security Rules ตรวจสิทธิ์แค่ `project.ownerId` ก็พอ
